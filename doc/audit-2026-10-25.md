# Halo GTK audit — October 25, 2026

Baseline: GitHub `main`, `430c3854f58b123b6611b8f9ae26f8d2e3d177ba`.
Changes are local on `codex/project-audit-2026-10-25`; they have not been
committed, pushed, installed into the user's running desktop, or tested with a
live Ring account. The previous checkout and eight older uncommitted changes
remain separately preserved from the synchronization step.

## Result

The current Python/GTK/aiortc/GStreamer design can be improved without replacing
the backend. This audit fixes confirmed state, cleanup, persistence, installer,
and dependency issues in that design. It also identifies unfinished features
and larger changes that need a separate decision. No backend swap or broad
application rewrite was performed.

All 49 baseline application modules and all six original scripts were reviewed,
along with their tests, dependency/build configuration, CI, desktop metadata,
schema, and documentation. New desktop-argument and installer helpers were also
reviewed and tested. The resulting tree contains 50 application modules, seven
scripts, and 45 test modules. Binary assets were checked through package/data
validation; this was not a visual redesign.

## Confirmed issues fixed

### Alarm command and state handling

- A confirmed mode request could wait behind another socket write while Alarm
  state changed. Admission now rechecks the exact approved revision and current
  session at the actual send boundary. Its confirmation waiter cannot accept a
  pre-send update. A stale request is rejected without sending it.
- An established WebSocket could keep the account marked Online after its hub
  went offline or switched to cellular backup. Status now becomes Degraded and
  recovers only after fresh, complete inventory.
- A socket handshake finishing after shutdown no longer publishes a late
  connection. Oversized integers, non-finite JSON numbers, and malformed ticket
  status remain inside the validated protocol-error boundary.
- Alarm panel rows prioritize active alarm evidence over a Disarmed mode label.
  External device names and confirmation-list text are rendered literally.

### History, views, authentication, and saved layouts

- Selecting another event or refreshing history stops the old recording and
  invalidates its pending request. A queued old end-of-stream callback cannot
  advance a newer recording.
- Delayed deletion matches camera plus event identity. It preserves a newer
  selection and restores its list row without restarting playback, so previous,
  next, and autoplay navigation still work. Matching event numbers on another
  camera are no longer removed from the view.
- Siren confirmations retain their original camera and authenticated client;
  switching cameras/accounts invalidates old confirmations.
- Focused snapshots use view generations, preventing an old result from
  repainting a hidden or replacement view. Settings email caches and worker
  results are similarly bound to the active account client.
- OTP Enter-key activation cannot submit a second sign-in while one is pending.
- A temporarily missing camera no longer causes an ordinary refresh to delete
  its saved monitoring layout. Overflowing persisted layout IDs are skipped.

### Ring inventory and media lifecycle

- The pinned Ring SDK refreshed device data without invalidating its cached
  collection. A bounded per-instance adaptation now discovers additions/removals
  before group discovery. State-only refresh retains device identity, and
  existing streams retain the original device/registry needed for cleanup.
- Failed, false-returning, and cancelled FCM startup now close partially
  allocated listeners before retrying. A loop-teardown submission race closes
  rejected coroutine objects.
- A failed session stop no longer prevents the remaining sessions from being
  cleaned up. Failed startup/release removes unusable registry entries and
  preserves the original startup error.
- Immediate microphone pipeline failure cannot report successful capture.
  Samples completing after push-to-talk release are discarded in favor of
  silence. Unsigned PCM now has the correct zero point/amplitude, and output is
  explicitly little-endian S16.
- Video dimensions and audio rate/channel changes renegotiate GStreamer caps
  rather than retaining the first frame's format.

### Storage, health, and desktop integration

- Favorite downloads stage outside the index transaction, keeping history reads
  responsive. Completed files publish under the lock. Device IDs distinguish
  archives from identically named cameras, and failed staging files are removed.
- Malformed favorite collections, overflowing numeric settings/health fields,
  null paths, and invalid path bytes no longer break the corresponding views.
- Wireless LAN is no longer classified as Ethernet. Explicit offline state
  takes priority over cached signal strength; missing signal remains Unknown.
  Missing battery health is no longer evidence that a camera is hardwired.
- Relative XDG environment values fall back to the standard home locations in
  both the application and install/uninstall scripts. Log cleanup skips symlink
  targets, including active handlers, and preview cleanup handles dangling links.
- Launcher/desktop publication uses atomic replacement. Existing symlinks are
  replaced without truncating their targets. Shell and Desktop Entry escaping
  preserve special characters in checkout/home paths; autostart shares the same
  desktop quoting helper.
- Installer shutdown matches the current user's exact executable arguments
  instead of an unescaped process regex. A process that will not stop blocks
  replacement. Shutdown now precedes virtual-environment recreation.

## Dependencies and security

The initial production audit reported **52 advisory records across six
packages**, including two records for the same OAuthlib advisory. This is a
dependency-advisory count, not 52 demonstrated exploits in Halo.

| Package | Previous lock | Updated lock |
| --- | --- | --- |
| aiohttp | 3.14.3 | 3.14.5 |
| certifi | 2026.2.25 | 2026.10.23 |
| multidict | 6.7.1 | 7.2.1 |
| Pillow | 12.3.0 | 13.0.0 |
| urllib3 | 2.7.0 | 2.8.0 |
| yarl, required by the refreshed graph | 1.23.0 | 1.25.1 |

Direct aiohttp/Pillow minimums were raised, and the lock was regenerated. The
updated production graph contains 38 resolved packages on this platform. Its
raw audit reports only the duplicated OAuthlib finding; the CI policy passes
with exactly that scoped exception. No other advisory is suppressed.

OAuthlib 3.3.1 remains because ring-doorbell 0.9.14 declares `<4`. The
[upstream PKCE advisory](https://github.com/oauthlib/oauthlib/security/advisories/GHSA-xpv3-w29h-x7cv)
affects authorization-server verifier comparison. Halo uses a password-grant
client against Ring and does not host that server. The advertised 3.3.2 fix was
not available on PyPI at audit time, while published 4.0.0 is outside Ring's
range. `SECURITY.md` documents the exact CVE exception and removal conditions.

The existing Dependabot configuration now includes weekly uv updates, in
addition to monthly Actions updates. GitHub supports the
[uv ecosystem](https://docs.astral.sh/uv/guides/integration/dependabot/).
This configuration takes effect only after these changes reach the repository;
it does not auto-merge dependency upgrades.

## Unfinished features and remaining engineering work

| Priority | Area | What remains |
| --- | --- | --- |
| High | Live Ring validation | Alarm has only synthetic fixtures. Establish read-only hardware parity before any controlled mode testing. Camera login/2FA, reconnect, audio, PTT, renewal, and long-running monitoring also need live regression checks. |
| High | Preview download boundary | Recording-thumbnail decoding passes an SDK URL directly to `av.open()`, outside Halo's bounded HTTPS downloader. Define and test protocol/TLS/redirect, byte, total-time, and cancellation limits without downloading entire recordings just to obtain one frame. SDK snapshots also lack a Halo-side preallocation cap. |
| High | Runtime upgrade compatibility | Validate newer aiortc/PyAV against Halo's private patches and representative cameras; see the proposal below. |
| Medium | Alarm history and notifications | Alarm/sensor event history is explicitly unavailable. A dedicated CLAP-state-to-desktop-notification pipeline was not found; generic `notify_alarm` event handling does not establish complete Ring Alarm notification support. |
| Medium | Device families | Chime details/volume/test sound, grouped lights, and Ring Intercom workflows are explicitly planned in Devices. These are unfinished controls. |
| Medium | Operation feedback | Some history download/favorite/delete failures and asynchronous microphone errors are only logged. Show clear completion/failure/pending state and deliberate retry choices. |
| Medium | Device-setting writes | Rapid switch/spinner edits can overlap. Serialize or coalesce writes per device/setting and reconcile uncertain timeout outcomes. |
| Medium | Install/update recovery | Updating Git and synchronizing the current environment are not transactional. A failed later runtime check can leave an unusable update. Staging/rollback needs an installation-design change. |
| Medium | Stream performance | The current path makes RGB24/NumPy/bytes copies, may pad frames, and assumes 30-fps timestamps. Measure CPU, memory, queue growth, A/V drift, and four/six-camera behavior before changing the pipeline. |
| Medium | Saved media and packaging | A general local-media browser and AUR/Flatpak packaging remain planned. Favorites is a narrower existing archive. |
| Low | GTK main-loop work | Tray setup is deferred to an idle callback but still performs synchronous D-Bus operations. Large local-media scans can also block GTK. Prefer async operations after targeted profiling. |
| Low | Maintainability | Camera/history/settings modules mix UI, worker orchestration, and policy. Extract tested controllers/helpers incrementally; consolidate duplicated Alarm mode-availability rules and dynamic-row text conventions. |

Panic/dispatch, Alarm siren, locks/switches, schedules, and device configuration
are intentional exclusions from the experimental Alarm interface. Their absence
is not treated as an accidentally incomplete safety workflow.

## Replacement and rework proposals — not implemented

1. **First evaluate aiortc 1.15 / PyAV 17 rather than replacing the stack.**
   Upstream's [aiortc changelog](https://github.com/aiortc/aiortc/blob/main/docs/changelog.rst)
   identifies SCTP parsing hardening and PyAV 17 compatibility addressing a
   per-frame memory leak. Halo currently pins aiortc 1.14/PyAV 16 because of its
   H264 and connection-lifecycle adaptations. A separate compatibility branch
   should verify patch contracts, SDP/ICE, corrupted keyframe recovery, stream
   renewal, shutdown, PTT, and sustained memory use before changing those pins.
2. **Consider GStreamer WebRTC only if profiling justifies a backend swap.**
   [`webrtcbin`](https://gstreamer.freedesktop.org/documentation/webrtc/) provides
   peer-connection primitives and could consolidate media handling. Reduced
   copying or better hardware decode is a hypothesis until measured. A swap
   would require new Ring signaling, ICE, H264, PTT, plugin-packaging, and
   lifecycle validation. It requires your approval before implementation.
3. **Keep a separate stream broker optional.** A bridge could share streams
   among multiple consumers, but adds a service, credential owner, configuration,
   and failure boundary. No alternative broker was established as superior in
   this audit, so no replacement is recommended without a concrete requirement
   and compatibility trial.
4. **Plan staged update/rollback and controller extraction separately.** Both
   can improve reliability and maintainability, but change substantial ownership
   boundaries. They are reviewable follow-up proposals, not hidden audit churn.

GTK4/libadwaita remains appropriate for the native desktop UI. GStreamer's
[`gtk4paintablesink`](https://gstreamer.freedesktop.org/documentation/gtk4/index.html)
already supports native paintables and optional accelerated paths. Current
evidence does not justify replacing the UI toolkit, Secret Service storage, or
the entire Ring integration.

## Verification and practical limits

- **550 tests pass** in an isolated, frozen environment on Python 3.14.8, with
  real installed GI/media libraries plus offline fixtures and fakes.
- Ruff lint and format checks, lock freshness, all-module imports, compileall,
  strict schema validation, desktop-file validation, Bash syntax, and diff
  whitespace checks pass.
- Source distribution and wheel build successfully. The wheel is installed in
  a separate environment with hash-locked runtime dependencies, dependency
  consistency checked, and all modules/assets/license/entrypoint validated.
- Current-advisory auditing passes with the single documented, non-applicable
  OAuthlib exception. Raw before/after reports are retained with the audit
  deliverables, so the exception remains visible.
- Regression fixtures demonstrate the affected state and cleanup paths.
  Runtime regressions were also checked against unchanged baseline source to
  establish that they fail before the fixes.

There was no live Ring login, camera/microphone use, hardware command, production
installation, screenshot-based visual pass, multi-hour soak, or full
Python/distribution matrix run. An upstream ring-doorbell `BasicAuth`
deprecation warning remains; it does not fail the suite. Passing these checks
does not establish live Alarm compatibility or complete security coverage.
